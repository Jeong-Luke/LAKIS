# LAKIS 설치기 백신 오탐 대응 — 2026-09-09

## 접수 내용

사용자가 LAKIS 7.3.3 `setup.exe`가 바이러스 탐지로 인해 설치 도중 취소된다고 보고했다. 보고에는 백신 제품명과 탐지명이 포함되지 않아 Defender Antivirus 탐지인지 SmartScreen/Smart App Control 차단인지, 또는 타사 백신 탐지인지 확정할 수 없다.

## 확인 결과

- 기존 `dist/LAKIS_Setup.exe`는 Authenticode 서명이 없다.
- 기존 설치기는 여러 LAKIS 실행 파일과 공식 `7zr.exe`를 하나의 약 22MB 자체 압축 해제형 EXE 리소스로 포함한다.
- 자체 압축 해제, 임시 경로 실행 파일 추출, 자식 프로세스 실행은 정상 설치기에 필요하지만 악성 dropper와도 형태가 유사하여 휴리스틱 오탐 가능성을 높인다.
- 현재 Windows Defender 엔진으로 기존 7.3.3 로컬 설치 파일을 `-DisableRemediation` 사용자 지정 검사한 결과는 위협 0건이었다.
- 공개 검색에서 기존 SHA-256 `F43649308B17029A9CC0B6B6E4164732EDC6702962F79E9E2BC972927F1D468A`에 대한 탐지 기록은 발견되지 않았다.
- 정상 작동한다고 보고된 7.3.1 게시 설치기와 7.3.3 후보를 비교했다. 설치기 크기와 12개 내장 리소스 구성은 동일한 계열이며 아이콘, WebView2 DLL 3개, 공식 7zr, 스플래시 2개는 SHA-256까지 완전히 동일했다.
- 달라진 것은 다시 컴파일된 LAKIS 자체 EXE들의 해시다. 보관된 7.3.1/7.3.3 설치기 소스 스냅샷에서도 설치기 코드 차이는 발견되지 않았다. 현재 증거로는 설치 동작의 새 위험 행위보다 새 바이너리 해시에 대한 평판 부족 또는 특정 엔진의 일시 오탐이 더 유력하다.

## 적용한 대응

- 모든 자체 제작 EXE에 Product, Company, Copyright, ProductVersion, FileVersion 메타데이터를 추가했다.
- 서명 인증서가 있으면 `LAKIS_SIGNING_THUMBPRINT`와 `LAKIS_TIMESTAMP_URL`로 서명한다. 인증서가 없는 정식 빌드는 `LAKIS_ALLOW_UNSIGNED_RELEASE=1`을 명시해야 하므로 우발적인 미서명 게시를 방지하면서 무료 배포는 유지한다.
- 포함되는 자체 제작 EXE를 먼저 SHA-256 Authenticode 서명·타임스탬프한 다음 설치기에 내장하고, 완성된 설치기도 마지막에 다시 서명한다.
- 서명 또는 타임스탬프 결과가 `Valid`가 아니면 빌드를 중단한다.
- `Test-BinaryTrust.ps1`을 추가해 모든 EXE의 메타데이터, 서명, SHA-256 및 선택적 Defender 검사를 릴리즈 게이트로 검사한다.
- 최종 서명 파일이 오탐되면 동일 파일을 다시 빌드하지 않고 정확히 그 해시를 Microsoft Security Intelligence에 소프트웨어 개발자로 제출한다.

## 실제 검증

- 강화된 개발 후보 설치기 빌드: 통과
- 후보 설치기 메타데이터: `LAKIS Studio`, `7.3.3`, 파일 버전 `7.3.3.0`
- 후보 산출물 전체 Defender 검사: 위협 0건
- 미서명 후보에 `-RequireSigned` 적용: 의도대로 실패
- 실제 인증서 서명 검증: 현재 PC에 코드 서명 인증서가 없어 보류

## 남은 릴리즈 차단 조건

다음 정식 릴리즈는 Defender 검사와 SHA-256 공개를 필수로 한다. 무료 배포에서는 명시적으로 승인된 미서명 릴리스를 허용하고, 동일 백신·탐지명으로 반복 재현될 때 해당 최종 파일을 백신 업체에 오탐 제출한다. 서명 인증서는 추후 무료 경로가 확보되면 적용한다.
